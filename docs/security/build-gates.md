# ConvertIA — Build-Gate Catalogue (living)

> The operational catalogue of every guardrail: **when** it runs, **what** it
> blocks, **which tool** enforces it, and its **fail posture**. Companion to the
> [security-concept.md](security-concept.md) (the *why*). Living document — same
> conflict order and update rules as the concept doc.
>
> Gate IDs are stable (`Gnn`). The planes each Enforced-by cell names map to the
> [defense-in-depth planes](security-concept.md#3-defense-in-depth--the-enforcement-planes)
> L0–L5.
>
> Row narratives before this schema (delivery notes, review rounds, leg counts): `git show 20dd4f73867c:docs/security/build-gates.md`.

## 0. Policy

- **Two planes.** Each gate marked *(mirror)* runs both as a local git-hook
  (L1/L2/L3) **and** in CI (L4). Local = realtime; CI = clean-checkout backstop.
- **Performance budgets.** pre-commit (L1) **soft** target **< 10 s** (a soft target, not a
  hard contract: `gitleaks`, clippy on a cold changed crate and `tsc`/`eslint` can each approach
  it, so the heavy legs are diff- or glob-scoped to hold it); pre-push (L2) target **< 3 min**;
  anything heavier is **CI-only (L4)** or **release-only (L5)**.
- **Hooks run in parallel** within a plane; gates sharing a resource (e.g. one
  test DB-equivalent / one build dir) are merged into a single sequential wrapper.
- **Fail-closed by default.** A gate blocks on doubt. Only the explicitly listed
  gates are **fail-open** (skip when a prerequisite is genuinely absent), and only
  because another plane guarantees enforcement.
- **No bypass.** `--no-verify`, force-push, disabling a required CI check, **and
  `core.hooksPath` redirection** are forbidden (CLAUDE.md). The local L1–L3 plane is
  entirely git-hook-based, so `git -c core.hooksPath=<elsewhere>` (or a persisted
  `git config core.hooksPath`) silently disables ALL local hooks WITHOUT `--no-verify` —
  a functionally identical un-named bypass — so it is added to the forbidden set
  explicitly, checked at [build-loop.md](../process/build-loop.md) Step 0
  (`git config --get core.hooksPath` unset or == the lefthook path) and by G54 (which resolves
  the EFFECTIVE hooks dir, not a hardcoded `.git/hooks/`). A red gate is fixed, not bypassed.
- **Severity ≠ exit code** for custom gate scripts: *any* finding fails the gate;
  severity only drives output formatting.
- **Custom gate scripts are themselves tested** (positive **and** negative cases —
  every custom gate and fastpath detector ships a self-test that proves it FAILS on
  a planted violation, not only that it passes clean) under a narrowly-scoped
  self-test gate (G24).
- **Structural parsing over regex.** A gate that consumes a generated or structured file
  (JSON, TOML, YAML, a lockfile, an SBOM) parses it (`tomllib`, `json`, `serde_json`, a real
  YAML reader), never a regex, and a gate that cannot resolve or parse its input fails closed in
  CI. Two named exceptions, both over L(-1) inputs (see *Gates over L(-1) inputs* below): G56 reads
  the workflow files with a stdlib line reader over a frozen dialect, and plan-lint check 21 matches
  two marker lines of the G29 rule-(i) file, whose YAML G29's own run validates.
- **Diff-reading discipline.** Every gate that parses `git diff` output (G8/G21, G28, G70,
  G74) reads one pinned shape: `a/` and `b/` prefixes forced, blank context lines kept, hunks
  unmerged, paths from the repo root, no external driver and no textconv, every file read as
  text, non-ASCII paths literal, `GIT_DIFF_OPTS` scrubbed from the environment, and lines split
  on `\n` from bytes. Named residual: `diff.algorithm` and `diff.indentHeuristic` choose between
  equivalent renderings; every removed line is still a `-` line. Each script carries the pin as
  `GIT_DIFF_SYNTAX`; the rows cite this bullet.
- **Status and fail posture.** Every row states its build state in the Status cell — `live`,
  `live-partial (<live legs>; rest → <box>)`, `unbuilt → <box>`, or `dormant-until <box>`
  (wired, skipping with a notice until that box lands its target) — and its posture in the
  Fail-mode cell — `fail-closed`, `fail-closed; fail-open leg: <leg>`, `fail-soft`, or
  `informational`. Every fail-soft posture and fail-open leg has a `[[fail_open]]` row in
  [`scripts/gate-planes.toml`](../../scripts/gate-planes.toml) naming its covering plane; a
  target-absent skip is not a fail-open, it is the Status cell's box. Box ids appear only in the
  Status cell; delivery history lives in git.
- **Gates over L(-1) inputs.** A gate whose input is an L(-1) file authored in this repo (the
  workflows, `lefthook.yml`, the gate TOMLs, `engines.lock`) defends against a careless author,
  not an adversarial one; the adversarial-author control is the owner's L(-1) ack under G71, and
  G1 stays a quality amplifier. zizmor (G50) and actionlint (G49), which parse real YAML, are the
  primary workflow controls. The G56 line-reader dialect is frozen: further valid-YAML spellings
  get no new refusal rounds, while new G56 assertions stay in scope. A gate over third-party or
  fetched content (an upstream `action.yml`, a registry response, an engine archive) keeps the
  adversarial bar. Named residual: a valid-YAML spelling inside the accepted dialect that the line
  reader and GitHub's parser resolve differently, limited to the G56-only assertions.
- **Offline tolerance.** Any gate with a network step (advisory-DB refresh, rule
  fetch) **decouples** the refresh (warn-only) from the check (hard-fail against
  the local/vendored DB), and honours an offline env flag.
- **The dual review (G1) is a quality amplifier, NOT a security control.** Only the
  deterministic gates — **every `Gnn` except G1** — are security controls. The
  `Dual-Review:` trailer is self-attested and unverifiable, so a gamed trailer cannot
  ship insecure code — the gates either pass on a clean checkout or they do not. (The
  range is phrased "every gate except G1" rather than a numeric span, which drifts each time a
  gate is added; the catalogue is the authoritative span, and plan-lint check 11 asserts the prose
  never claims a span narrower than `max(Gnn)`.)
- **Gate toolchain: pinned and verified as a class.** Every gate, SAST, SBOM and lint tool
  (Semgrep, Syft, `gitleaks`, `zizmor`, `actionlint`, `typos`, `osv-scanner`, `cargo-fuzz`, the
  CycloneDX tools, `cdxgen`, `editorconfig-checker`, **`lefthook` (G54), `cargo-auditable` (G55),
  `minisign` (G39)**, …) is pinned by **exact version AND verified by checksum / image digest at
  install** — a vendored binary or a digest-pinned container is preferred over a live-registry
  `cargo install`/`npm -g` (a poisoned gate tool both misses a real finding and can read the CI
  secret). Where upstream publishes no prebuilt binary for a platform, `cargo install <tool>
  --version <x> --locked` is the checksum leg, because crates.io is content-addressed
  (`cargo-fuzz`: the route is recorded in the `scripts/gate-tools.toml` header, its corroboration
  in the `fuzz.yml` header).
  A pip-installed gate tool installs with **`pip install --require-hashes -r requirements-ci.txt`**
  (`pkg==ver --hash=sha256:...` entries — a bare version pin verifies only the string), with a
  planted positive that a hashless install fails. The fetch-and-verify mechanism is itself
  self-tested: a deliberately wrong checksum MUST fail the install (the G24 wrong-checksum
  self-test; `lefthook` carries it too, because it executes the whole L1–L3 plane and a poisoned
  one can no-op every local hook). At pin time each recorded checksum is corroborated against the
  tool's own published signature or attestation, or across ≥ 2 independent origins, and the
  corroboration is recorded in `scripts/gate-tools.toml` (the G37 acquisition discipline one tier
  down); a checksum edit is an owner-acked L(-1) act. The Rust toolchain is pinned in
  `rust-toolchain.toml` — an exact stable version plus a date-pinned `nightly-YYYY-MM-DD` for
  `cargo-fuzz` (G48), asserted not-floating. The trust boundary is everything that touches the
  minisigned bytes (spec §3.8): `cargo-auditable` and `minisign`, the digest-pinned CI base image
  and build container, the version- or digest-pinned C/C++ toolchain and Tauri CLI, and `lefthook`
  as the executor of the local plane. `cargo-mutants` (G15) and `diffoscope` (G60) are
  informational tools, pinned the same way but outside that boundary.
- **Current state only — git is the log.** This catalogue carries no review-round logs, idea
  lists or history sections: an adopted idea becomes a row or an entry in the "Vacated /
  reserved gate IDs" map (§5), and a declined one a `decided` row in
  [gate-status.md](../process/gate-status.md). The retired P0 review-round reconciliation logs
  (r1–r7) and forward-idea lists are read with `git show cf97638f7280:docs/security/build-gates.md`.
  A provenance citation — a review tag (`r7`), a `[Test-Change: …]` tag, "the P<n>.<m> note" or
  "ruling" — is a historical pointer resolved through git: never a freshness target, and not
  re-pointed when its source text is retired or condensed
  ([security-concept.md](security-concept.md) §6).

## 1. L0 — Build-Loop per box (the dual review, "holy grail")

| ID | Gate | Contract | Enforced by | Status | Blocks | Fail mode |

**G1 — Opus + Sonnet pre-commit dual review.** *Plane L0.* Two model reviewers (`opus` + `sonnet`) critique
each build commit's staged diff before the commit. The protocol lives in
[build-loop.md §3 Step 5](../process/build-loop.md#step-5--pre-commit-opus--sonnet-dual-review-g1) and is not
restated here. It covers the reviewer inputs and review brief, and the canonical rubric: its item 5 is the
semantic half of the no-green-by-rewrite discipline whose mechanical signal is G70, and its item 6 is the
owner's class-closure rule. It also covers the P0–P3 severity bar, the round cap and park, the post-GO rule
and the review record. The commit-message shape is Step 6; G12 checks the trailer at pre-push.
- **Definition-of-Done.** A box is "done" only when it satisfies the ConvertIA DoD
  (authored in [build-loop.md](../process/build-loop.md), P0.6): (a) spec-`§`
  referenced or marked tooling-only; (b) spec synced in the same commit; (c) tests
  at the highest sensible level green; (d) hard gates green with **no** `--no-verify`;
  (e) dual-review done + trailer present; (f) inline `[Build-Session-Entscheidung]`
  tags at non-spec choice sites; (g) `engines.lock` + SBOM row if a new engine was
  staged; (h) §0.11 + security-concept §5 row if a new threat class was introduced.
- **No skip.** No commit skips it (the check-off rides in the box commit); an
  `[!extern]` box is not built by the loop, so it yields no commit.
- *Blocks:* the build commit (self-gate; the trailer is also checked at pre-push by
  G12).

## 6. The `plan-lint` / `spec-lint` doc-consistency gate (G7/G20)

A single **stdlib-only** script that treats the canonical docs as machine-checkable truth. Exit codes:
`0` none, `1` ≥1 finding (**any** severity), `2` no plan box found or a usage error. CLI: `--check <id>`,
`--json`, `--quiet`, `--max-per-check N`; the read-only modes `--next`, `--show <id>` and `--report
owner-acts --phase <n>` (exit 0 answered, 1 nothing buildable, 2 a usage error, a malformed plan or a
malformed parked set). Call sites: L1 (`--quiet`, every commit), L2 (full), L4. The doc set is every
repo-tracked `.md` at the repository root and under `docs/`: the `git ls-files` set, so an untracked or
ignored file is no doc (with `git` unavailable, every such `.md` on disk, and checks 7 and 26 report the
unavailable `git`). **A missing target is a finding:** every check over a landed target reports its
absent, empty or unparseable source-of-truth target as a finding, never a skip; checks 3, 4, 6, 7 and 9
scan whatever their scope holds, and check 31 reads the plan itself (no plan box exits `2`). A retired
check keeps its number and its line below, with no function behind it.

**Base case.** The G24 canary [`g24-plan-lint.py`](../../scripts/gate-selftests/g24-plan-lint.py) drives
each check over fixtures, planted violations included, and asserts that the real repo exits 0, so a check
blunted into silence reds the canary: on every L4 run, and at L2 when the push range touches the gate
plane.

Each item: what the check catches, its scope, its posture when its target is missing, and its function.
